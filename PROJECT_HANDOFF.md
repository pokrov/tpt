## Daily generation and calendar

`cron_job.py` validates configuration, selects specs, generates each book independently, persists each success and continues after per-book failure. Exit status indicates partial failures while completed PDFs remain. Daily generation uses the default reading/QCM type; the web form supports both types.

`local_server.py` records local_daily.attempted_on before generation, then records completion/exit code on ordinary completion. Exceptions/interruption leave the attempt marker, preventing automatic repeat spending that day; a manual retry remains possible. Optional schedule checks every 30 seconds after the configured time, handles late starts for the current date and does not backfill missed days. Memory-only jobs do not resume after restart. One process/worker is required for coordination. Generation requires Windows awake and Docker running.

`calendar.json` sets start_offset_days=7 and end_offset_days=37. Inclusive overlap logic handles fixed dates, months, cross-year ranges, nth/last weekday rules, Easter offsets, week-containing rules and explicit year dates. BOOK_TIMEZONE defines today. Real dated events take precedence over seasonal teaching windows; evergreen topics are fallback. A batch selects one event, varying angles/grades; recent theme/grade pairs are avoided where possible. Daily grade cycles are shuffled across the two bands; manual default grade chooses the least recently used band.

Catalog displays dated events chronologically with full dates/ranges and separates undated topics. Event-based title selection returns event_name; retained title_keywords apply to undated/evergreen topics. Explicit religious-date tables cover 2026-2027 and require maintenance afterward; absent years are not guessed. Ramadan dates carry community/provisional notes.
